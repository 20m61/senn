# SENN Ecosystem and Business Model

## Principle

SENN does not monetize by closing the core.
SENN grows by making the core open and creating a trusted ecosystem around add-on distribution, verification, deployment, and support.

## Open Layer

Always open:

- Core runtime
- Add-on SDK
- Add-on manifest specification
- Message envelope specification
- Permission model
- Local storage APIs
- Sample add-ons
- Developer tools

## Trust Layer

Potential business:

- Verified Add-on Registry
- Add-on signing
- Security review
- License review
- Compatibility badges
- Official distribution
- Private add-on registries

## Enterprise Layer

Potential business:

- Official hosting
- Enterprise deployment
- Custom add-on development
- Private registries
- Support contracts
- Security consulting
- Training
- Partner certification

## Community Economy

Third-party developers can:

- Publish free add-ons.
- Sell paid add-ons.
- Provide custom add-ons.
- Offer event-specific add-ons.
- Provide XR experiences.
- Build education tools.
- Become certified partners.

## What SENN Must Not Do

- Close the core API.
- Require official servers for core P2P use.
- Prevent self-hosting.
- Prevent community add-on distribution.
- Charge for basic P2P communication.
